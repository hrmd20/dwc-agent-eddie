# Optional iPhone message treatment

Use only when messages or notifications on screen are requested. This is an opt-in exception to the default still-image and no-animation rules.

- Use the supplied message wording, sender labels and timestamps. Ask for missing copy rather than inventing it. For illustrative examples, agree display timestamps; do not imply fabricated timestamps are actual patient records.
- Render rounded, translucent frosted-glass iPhone-style notification cards with readable dark text, sender and timestamp hierarchy. Preserve the speaker and keep cards below stationary Eddie captions with clear separation. Long messages must fit legibly; split into successive cards if needed without silently shortening copy.
- Enter with a smooth, gradual upward slide and gentle settling, avoiding abrupt jumps or bounce. Hold while the speaker discusses the message; exit cleanly at the topic change. Calibrate timings to actual speech, not a fixed duration per message.
- Play one notification cue per message entrance using the supplied or authorized sound. Keep speech clear and avoid repeated cues while a card stays visible. Do not assume a proprietary sound file is bundled.
- When the user requests a blurred first round, show each card and cue at its announcement with message-body text genuinely obscured. Reveal the same message for its detailed discussion. Confirm every decoded frame of the blurred section remains unreadable.
- An optional rounded white text hook with black lettering follows the requested wording, placement and duration; do not add one automatically.
- Check the encoded output for full message spelling, sender names, timestamps, readable holds, caption separation, face clearance, smooth motion and sound timing. Keep patient-specific copy, media and audio outside the public skill repository.
