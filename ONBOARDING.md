# EDDIE first-use welcome flow

Apply when the user asks to start/set up EDDIE, asks how to use the downloaded package, or pastes the START HERE prompt. Opening/downloading files alone cannot trigger execution. Do not interrupt a concrete editing request with a mandatory onboarding questionnaire.

## Welcome and gather only what is missing

Say briefly: “Welcome to EDDIE. I can help turn your recording into an edited video. Share your video and where you want the finished file saved; I can choose the style for you.” Adapt to information already supplied. Do not ask again for a known file, destination or approved style.

Present the five Master Editor modes only if useful: captions + hook; captions + images + hook; Rapid Fire; Sync Reaction (simultaneous corner inset); Async Reaction (source first, then separate full-screen response). Explain in ordinary language. Landscape and Carousel are additional workflows. Load the corresponding skill before editing. Do not ask beginners to run project commands or edit JSON.

## Check readiness before promising a render

Inspect available tools for this specific job: read/inspect video, transcribe with word timing, render captions/images and export. Reuse existing local runtimes and wrappers. For Carousel, check the user's own editable Canva template and connected access instead. Do not require Canva, Google Drive, social accounts or paid voice tools for ordinary local video edits.

Report “Ready to edit” only when the needed capabilities are available. If something is missing, identify the concrete missing tool and simplest next step, and offer guided setup within available permissions. Do not claim the package bundles dependencies or automatically installs them. Do not use hardcoded developer machine paths or credentials. Provider sign-in belongs in the provider's secure interface.

## First project

Recommend a style from the actual footage/script and explain why in one sentence. For reactions identify source versus doctor footage and Sync versus Async. For Rapid Fire retain recorded questions and answers; ask about AI questions only if needed and do not generate a voice without a request.

If the user invokes the START HERE prompt, deliver a short preview (normally 10 seconds) or storyboard and wait for feedback before the full export. This is the requested preview scope, not a permanent approval gate: an explicit full-edit request authorizes completing the edit. Avoid repeated preference questions. State any material crop/asset decisions in the preview.

Use a private project folder and keep original media intact. Record style, supplied preferences, source ranges and output location there as needed. Do not put practice preferences, medical footage, transcripts or credentials into public repository files. Do not create recurring tasks or connect/post to social accounts as part of onboarding.

For delivery, link the actual output, state what was checked and mention any concrete limitation. Never claim a render or listening review occurred if it did not. Follow the selected skill's framing/caption rules and 200% gain once with peak protection for all Master Editor modes.
